# 見積書作成ワークフロー（quote_automation）

このリポジトリの `quote_automation/` を使い、仕入先の原価資料（PDF・Excel・メール本文など形式問わず）→客先向けExcel見積書を作成する。
詳細な背景・スキーマ・開発者向け情報は `quote_automation/README.md` を参照。
このSKILLは「毎回チャットで確認すべきこと」と「うっかり忘れやすい既定仕様」を
チェックリスト化したもの。

## 手順

1. アップロードされた仕入先の原価資料を読む（Readツール）。**PDF・Excel・
   チャット本文に貼られたメールのテキストなど、形式は問わない**。仕入先が
   どの形で原価を送ってきても、同じように読み取って2で選んだ形式へ転記する
   （2026/10/03、前島様よりご指摘。PDF以外は転記できない、という思い込みをしない）。
2. **最初に「原価に対して％を乗せる（加工品）」か「重量(kg)に換算してキロ単価に
   円/kgを乗せる（鋼材・一次加工）」かを選択式で確認する**
   （2026/10/01・2026/10/03、前島様よりご指摘）。見積りの種類によって
   テンプレート・転記方法が異なるため、作成を始める前に必ず聞く。
   **判断基準は「品名に“加工”と付くかどうか」ではなく、原価が重量(kg)に
   素直に還元できる性質かどうか**:
   - 鋼材・一次加工（％ではなくキロ単価方式） → 母材・切り板そのものに加えて、
     それに付随する**一次加工**（穴明け、面取り、切断など）も含む。
     仕入先が個単価・枚単価で見積りを出してきた場合でも、**その単価に
     素直に％を掛けると価格が大きく歪むため、必ず重量で割ってキロ単価に
     引き直してから、キロ当たり何円乗せるかで客先単価を作る**
     （前島様の実務感覚：穴明け・面取り程度の一次加工は、従来の「加工品」が
     想定する組立・複雑加工とは別物で、材料に近い）。
     → 下記「鋼材（材料）見積り」の節（`fill_steel_quote.py`）、または
     単純な総重量×キロ単価のみなら「総重量(kg)×キロ単価」方式
     （`fill_weight_quote.py`）。
   - 加工品（原価×％方式） → 購入部品・電装品・複雑な組立加工など、重量に
     還元する意味が薄く、原価に対する％上乗せが素直に成立するもの。
     → 下記の通常手順（仕入単価×上乗せ率、`fill_quote.py`）。
   迷う場合（例:「加工」という言葉が付いているが母材や切断を伴う）は、
   上記の判断基準をそのままチャットで示し、ユーザーに選んでもらう。
3. 以下をチャットで1つずつ確認する（省略しない）。**必ず選択式（AskUserQuestion
   などの択一回答形式）で聞く。自由記述を求める聞き方はしない**
   （2026/10/01、前島様よりご指摘。企業名のように選択肢を作りにくい項目は、
   候補案を2つ以上の選択肢として提示する形にする）:
   - 提出先の企業名・担当者名（似た過去案件があれば「前回と同じでよいか」を確認）
   - 上乗せ率（%）。品目ごとに率を分けたいか、客先単価を直接指定したいか
   - 備考・注意事項（仕入先資料の特記事項等をそのまま転記してよいか）
   - 納期／受渡場所・決済条件・検収条件（既定と違う場合のみ）
   - 捺印の要否・位置（後述、既定は「入れる」）
4. `quote_automation/extraction/confirmed_quote.py` のJSONスキーマに沿って確定させ、
   `step2_fill_template.py` で転記 → `step3_verify_calculation.py` で検算 → OKなら完了
   （**PDFは既定では作らない**。「PDFも」と言われたときだけ`step4_export_pdf.py`）。
   鋼材（材料）見積りなど`step2_fill_template.py`の対象外の形式は、
   LibreOffice再計算（`soffice --headless --convert-to`）による手計算との
   突き合わせで検算する（詳細は各節を参照）。
5. 見積り集計表（`work/summary/quotation_ledger.xlsx`）に自動追記される
   （`step2_fill_template.py`対象外の形式は手動で1行追記する）。
6. 作成後、`mcp__Claude_Code_Remote__send_later`で約1週間後に受注状況確認の
   リマインダーを自分宛てにスケジュールする。

## 「総重量(kg) × キロ単価」方式の見積り（別形式）

鋼材の孔明け加工費など、仕入単価への上乗せ率ではなく**重量×キロ単価**で
金額を出す案件は、上記の仕入単価×上乗せ率方式とは別物。
`quote_automation/template/fill_weight_quote.py` と
`quote_automation/assets/weight_based_quote_template.xlsx` を使う
（`fill_quote.py`/`base_quote_template.xlsx`とは別のテンプレート・列構成：
品名・式・キロ単価・総重量(kg)・金額・備考）。

- 図面・明細から部材ごとの寸法（幅×厚×長、mm）と個数を拾い、
  鋼材比重7850 kg/m³（孔明け前の素材重量、孔の体積は引かない）で
  1点ずつ重量を計算し合算する。品目数が多い場合は手計算せずPythonで集計する
- 金額 = 総重量 × キロ単価。四捨五入等の丸めは行わず、テンプレート側の数式
  （`=キロ単価セル*総重量セル`）でそのまま計算する（客先の過去の実例に
  合わせた仕様。ROUND等を勝手に挟まない）
- 見積№・捺印は通常の見積書と同じルールで付ける
  （`fill_weight_quote_sheet()`のquote_number/stamp_path引数）
- 受渡場所は案件ごとに大きく異なるため既定値を設けていない。必ずチャットで確認する

## 鋼材（材料）見積り（別形式）

仕入先（鋼材商社）から「板厚×幅×長さ×数量」の寸法表形式で原価見積りを
受け取る鋼材案件向け（実案件をもとにテンプレート化、2026/10/01）。
加工品の見積り（仕入単価×上乗せ率）とも、重量×キロ単価見積り
（上記）とも別物。`quote_automation/template/fill_steel_quote.py` と
`quote_automation/assets/steel_material_quote_template.xlsx` を使う。

- 明細は8枠（18〜25行目）。1行＝板厚・幅・長さ・単重量(kg)・数量・
  総重量(kg、=単重量×数量)・客先単価(円/kg)・客先枚単価(円)・客先合計金額(円)。
- **原価は品目ごとに印刷範囲外（M〜P列）へ転記する**。仕入先見積りPDFの
  「板厚ごとの枚単価（製品価格）」をそのままO列に入力するのが基本
  （kg単価は仕入先側も「参考」扱いのことが多く、四捨五入で総額がズレるため、
  原価単価(円/kg)はN列で`=O/E`として製品価格から逆算する数式にする。
  Oを直接入力、Nは数式、が原則）。
- **％の上乗せ率ではなく、円/kgの定額乗せ**を使う（P16セル、ラベルはP16の
  右のQ16に置く＝「値→ラベル」の順。O16など品目の原価データ列と同じ列に
  ラベルを置いて紛らわしくしない。`fill_steel_quote_sheet()`のmarkup_per_kg
  引数）。客先単価(H列)は`=原価単価(N)+$P$16`の数式になり、P16を書き換える
  だけで客先単価・客先枚単価・客先合計金額・総計金額（税抜/税込）まで
  連動して再計算される。M17のような％の仕組みは今回は使わない
  （2026/10/01、前島様よりご指摘）。
- **運賃も固定値を直書きしない**。原価(P26)と掛け率(Q26、例: 20%増しなら1.2)
  をセルに入れ、客先向け運賃(J26)は`=ROUND(P26*Q26,-3)`のライブ数式にする
  （`fill_steel_quote_sheet()`のfreight_cost/freight_multiplier引数）。
  乗せ代(P16)とは別建てで連動させないのが既定だが、「電卓で計算して
  数値だけ書き込む」のは禁止——過去に固定値で納品し、後から掛け率入りの
  数式に直された実例がある（2026/10/01）。計算できる金額は必ず数式にする、
  という原則は運賃にも例外なく適用する。
- 合計行の下（M28/P28）に利益行（`=客先合計(J27)-原価合計(P27)`）を
  自動で表示する。原価割れしていないかをその場で確認できるようにする。
- **受渡場所はこの形式では既定値を設けていない**。「貴社車上渡し」を
  安易な既定として使わない。仕入先見積りPDFの納入先設定・発送エリアの
  記載（例:「愛知県発送　チャーター便」）も参考にしつつ、必ずチャットで
  確認する。AskUserQuestionの一括確認が見送られた場合も、受渡場所だけは
  納品前に改めて確認すること（2026/10/01、確認を怠ったまま既定値で
  納品し、後から実際の受渡場所に手直しされた実例あり）。
- 原価合計（P27）が仕入先見積りPDFの合計金額と一致することを確認してから
  納品する（鋼材.加工費＋運賃の合計）。
- `step2_fill_template.py`・`step3_verify_calculation.py`の対象外のため、
  LibreOffice再計算（`soffice --headless --convert-to xlsx:...`で再計算後の
  値を読み直す）で、原価合計が仕入先PDFの合計と一致するか、客先単価が
  `原価単価+乗せ代`と一致するか、利益行がマイナス（原価割れ）になって
  いないかを確認してから納品する。
- 見積№・捺印は通常の見積書と同じルール
  （`fill_steel_quote_sheet()`のquote_number/stamp_path引数）。

## 絶対に忘れてはいけない既定仕様

- **単価はExcel数式のまま（live_formula）にするのが既定**。
  全品目が同じ上乗せ率を使う見積り（特に1品目だけの見積り）では、
  `items[].live_formula: true` を必ず付ける。これにより客先単価は
  `=ROUNDUP(仕入単価×$M$17,-2)` という数式のまま残り、後でM17（上乗せ率セル）
  を書き換えるだけで単価が自動的に再計算される。過去、これを付け忘れて
  「利益率を変えても単価が自動で変わらない」と指摘されたことがあるため、
  **通常の計算済み数値（customer_unit_priceの直接指定を除く）で出力するのは、
  品目ごとに上乗せ率が異なり$M$17を共有できない場合など、live_formulaが
  使えないケースに限る**。迷ったらlive_formulaを使う。
  - **live_formulaは基本100円単位で切り上げる**（`excel_roundup`、
    `LIVE_FORMULA_ROUND_DIGITS = -2`）。以前は円単位の四捨五入だったが、
    単価が1円単位までバラつく（例: 9,612円）のは見積書として細かすぎると
    指摘されたため、既存の1000円単位切り上げ（明細ごとの通常計算、
    `ROUND_DIGITS = -3`）よりは細かく、100円単位で切り上げるよう変更した。
  - customer_unit_price（単価直接指定）とlive_formulaは併用不可。
- **総計金額は税抜・税込の両方を明記する**（既定で標準仕様）。テンプレートの
  C8「総計金額（税抜）：￥」の下、C9「（税込10%）：￥」に消費税10%込みの
  金額を自動計算して表示する（D9 = ROUND(D8*1.1,0)、テンプレート側の
  固定数式のためコード側で個別に書き込む必要はない）。明細行・単価は
  従来通り税抜ベースのまま変更しない。
- **見積№は既定で自動採番する**。`quote_automation.scripts.update_ledger.generate_quote_number()`
  で発行し、`fill_quote_template()`/`fill_quote_sheet()`の`quote_number`引数に渡す
  （H4に「見積№：〇〇」の形式で表示される）。採番ルール：「HK-」＋見積作成年月日
  （yyyymmdd）。同日に複数件発行する場合は2件目に「-2」、3件目に「-3」…と
  枝番を付ける（見積り集計表の同日の行数から自動判定するため、手動で数える必要はない）。
  手動で番号を指定したい特殊なケースのみ`confirmed_quote.py`の`quote_number`を上書きする。
- **捺印は既定でつける**（`config.STAMP_IMAGE_PATH` = `work/assets/maejima_stamp.png`
  が存在する場合）。このファイルはGitにコミットしないセッションローカル管理のため、
  セッションが変わって存在しない場合は、捺印画像（またはそれが写った資料）の
  再アップロードを依頼するか、今回は捺印なしで進めてよいか確認する。
  位置は既定（宛先企業情報欄付近）でよいか、都度チャットで確認・調整する。
- **PDFは既定では作らない**。Excelのみで完了とする。
- 印刷範囲は備考欄の実使用行数に応じて自動で縮む（`fill_quote_sheet`が
  毎回`ws.print_area`を設定し直す）。備考欄そのものの手動フォーマット調整は不要。
- Box同期フォルダ配置用のzip化（`quote_automation/scripts/bundle_for_box.py`）は
  **毎回「今回も作りますか」と確認してから**行う。自動では行わない。
- 出力前に必ず`step3_verify_calculation.py`で検算し、OKになってから納品する。
- 新しいバイナリ資産（テンプレート等）をコミットする場合や、コード中の
  サンプルには実在の客先名・仕入先名・金額を書かない（README「機密データを
  Gitに載せないためのルール」参照）。捺印画像など個人情報を含む資産も同様に
  Gitにコミットしない。

## 困ったとき

- テンプレートの見た目がおかしい（罫線のずれ等）に気づいたら、その場の
  出力だけ直すのではなく `quote_automation/assets/base_quote_template.xlsx`
  自体の不具合を疑い、テンプレート側を修正してコミットする
  （過去に備考欄下の余分な罫線が残っていた例あり）。
- 集計表（`work/summary/quotation_ledger.xlsx`）はセッションをまたぐと消える。
  セッション開始時に前回分の再アップロードがなければ、ゼロから作られる旨を
  ユーザーに伝える。
