# 見積書作成 自動化ツール 運用ガイド

仕入先PDF見積を読み取り→自社Excel見積書テンプレートへ転記→利益上乗せ計算→PDF化、
までを自動化するツールです。客先へのメール送付は対象外（引き続き手動）です。

## 会社PCには何もインストールしません

処理（PDF読み取り・OCR・Excel転記・PDF化）はすべて **Claude Code on the web の
クラウドセッション内** で行います。会社PC側でやることは、

1. ブラウザで Claude Code on the web を開く（このリポジトリのセッション）
2. 仕入先PDFをアップロードし、Claudeとのチャットで内容を確認する
3. できあがったファイルをダウンロードする

の3つだけです。Python・Tesseract OCR・LibreOfficeなどは、セッションが始まると
自動でクラウド側にインストールされます（`.claude/hooks/session-start.sh`）。
会社PCへの新規ソフトインストールは一切不要です。

---

## 日々の運用（アップロードは仕入先PDF1枚だけ）

事前にExcelテンプレートを用意したり、確認用シートをダウンロード→編集→
再アップロードする必要はありません。**仕入先PDFをチャットに送るだけ**で、
残りはすべてチャット上のやり取りで完結します。

1. チャットに、仕入先から届いたPDF見積を**アップロード**する
2. Claudeが読み取り、以下をチャットで1つずつ確認してくる
   - 見積書番号・日付・金額・明細（品名・数量・単価）… OCRでの読み取りが
     不確かな箇所や、テーブルとして拾えなかった項目を提示するので、
     元PDFと見比べて正しい数字を回答する
   - **提出先の企業名・担当者名**
   - **上乗せ率（%）**（仕入単価に対して何%乗せるか。客先単価は
     「仕入単価 ×（1+上乗せ率%）」を**1000円単位で切り上げ**て作成する。
     材料費・加工費・納入費のように**明細ごとに率を分けたい場合はその旨を
     伝えれば、明細1件ずつ別々の上乗せ率で計算できる**。指定しなかった明細は
     全体のデフォルト上乗せ率が使われる。「〇〇円ちょうどにして」のように
     **上乗せ率ではなく客先単価そのものを直接指定することも可能**。
     また「率は後で変えるかもしれない」場合は、その旨を伝えれば**単価を
     Excel数式のまま残し、上乗せ率セル(M17)を書き換えるだけで単価が
     自動的に再計算されるようにできる**（1000円単位の切り上げではなく
     円単位の四捨五入になる。1明細だけの見積り向け）
   - **備考・注意事項**（仕入先見積に書かれている文言をそのまま転記する。
     転記内容は書き込む前にチャットで確認する）
   - 必要であれば**納期**や、**運賃を明細と別立てにするか**（既定は
     「運賃込み価格」の一文だけ。別立てにする場合は運賃専用の明細行に
     金額を表示し、見積条件欄の表記も「別途運賃」等に変わる）
   - 客先ごとに決まった**受渡場所・決済条件・検収条件**がある場合は
     それも伝える（既定は「貴社車上渡し」「従来通り」。検収条件は
     指定がなければ欄自体を表示しない）
3. すべて確定したら、Claudeが自社見積書テンプレートに転記し、計算結果を
   検証したうえでExcel見積書を作成する（**PDFは既定では作らない**。必要な
   ときだけ「PDFも」と伝えれば作れる）
4. できあがった**Excel見積書**をダウンロードする
5. 内容を確認し、**これまで通り手動で**客先へメール送付する

出力される見積条件は以下のルールで自動生成される：
- **見積有効期限**：この見積書の作成日（右上の日付）から**+30日**
- **品名・物件名（題名）**：仕入先見積の項目名をそのまま使用
- **出力ファイル名**：`【見積書】〇〇〇.xlsx` （〇〇〇は品名・物件名）
- **印刷範囲**：備考欄に書いた行数に合わせて自動で縮む（備考が少ない見積りで
  ページ下部に大きな空白ができないよう、実際に使った行の1行下で枠を閉じる）

途中でエラーになった場合は、Claudeが理由（宛先未確認、数量未確認、計算結果の
不一致など）を説明するので、チャットで訂正してやり直してください。

**上乗せ率違いの案を複数ページにまとめたい場合**（例: 交渉代を見込んだ当初案と、
実際に通った最終案の2案を1つのファイルで見比べたい）は、その旨を伝えれば、
**1つのExcelファイルに案ごとのシート（当初案・最終案）を作り、そのままPDF化すると
自動的に複数ページのPDFになります**（`fill_quote_workbook()`。シートが増えても
Excel側で開いた時も見やすいので、こちらが基本の方法です）。

## 見積り集計表（実績の記録）

見積書を1件作成するたびに、**見積り集計表**（`work/summary/quotation_ledger.xlsx`）
に自動で1行追記されます。記録する項目は、年月日・客先名/客先担当者（売り先）・
仕入先名/仕入先担当者・名称（品名・物件名）・仕入金額・売り金額（見積時）・
利益率(%)・利益額（見積時）・受注状況・決定金額です。

- 受注状況・決定金額は見積り作成時点ではわからないため、まず「未定」・空欄で
  記録されます。受注できた場合もできなかった場合も、決定した金額が分かれば
  分析のために記録します（受注できなかった案件も含む）
- 仕入先名・仕入先担当者は自社見積書（客先向けPDF）には転記されません。
  集計表にのみ記録する社内用の情報です
- **見積り作成から1週間ほど経ったら、Claudeから受注状況・決定金額を
  確認する連絡が入ります**（`send_later`で自動的にスケジュールしています）。
  回答すると集計表の該当行が更新されます
- 客先名・金額・利益率など**機密情報を含むため、この集計表はGitリポジトリには
  コミットしません**。`work/`配下だけで管理します
- そのため、**セッションが終わると集計表も消えます**。継続して蓄積したい場合は、
  セッションの最後に集計表もダウンロードしておき、次回セッションの最初に
  同じ場所（`work/summary/quotation_ledger.xlsx`）に再アップロードしてから
  見積り作成を進めてください。再アップロードしなければ、新しい集計表が
  ゼロから作られます

## 機密データをGitに載せないためのルール

このリポジトリはPublicです。実在の客先名・仕入先名・金額など、実データが
Gitに残らないよう、以下を徹底しています。

- `.gitignore`で `*.pdf` `*.xlsx` `*.xlsm` `*.csv` を**リポジトリ全体で一律禁止**
  にしています（`work/`配下に限らず、置き場所を問わず防ぐ多重の安全策）。
  例外は `quote_automation/assets/*.xlsx`（客先名等が空の共通テンプレートのみ）
- コード中のサンプル・使い方の例には、実在の客先名・仕入先名・金額を
  **絶対に書かない**。ダミーの会社名・金額（例:「サンプル工業株式会社」
  「テスト製鋼株式会社」）のみを使う
- 動作確認・スモークテストも実データではなくダミーデータで行う
- 新しいバイナリファイル（xlsx/pdf等）をコミット対象に加える場合は、
  中身に実データが入っていないか（セル値だけでなく、Excelのシート名・
  作成者情報等のメタデータも含めて）確認してからにする

## 制限事項・注意点

- 明細は1見積につき最大17件まで（テンプレートの行数に合わせています。運賃を
  別立てにする場合はさらに1件追加できます）。これ以上必要な場合は
  `quote_automation/scripts/_rebuild_template_for_n_items.py`でテンプレートの
  明細枠を再構築できます（開発者向け）
- 仕入先ごとにPDFのレイアウトが異なるため、OCRでの自動読み取り精度は
  仕入先によってばらつきます。**チャットでの確認は毎回省略しないでください**
- 運賃を明細と別に立てたい場合など、現状のテンプレート構成から外れるケースは
  別途相談してください
- クラウドセッションの作業フォルダ（`work/`）はセッションが終わると消えます。
  必要なファイルは都度ダウンロードして手元に保存してください
- テンプレートの備考欄は34〜44行目を使用します（29〜33行目は別用途の
  非表示行のため使いません。書いてもPDFには出てきません）
- 自社の空テンプレート（客先名・担当者名などは未入力で、自社情報と数式だけが
  入ったもの）は `quote_automation/assets/base_quote_template.xlsx` として
  リポジトリに常備されています。案件ごとに客先名等を書いたテンプレートを
  用意する必要はありません

## 開発者向け：処理の流れ

1. `step1_extract_supplier_quote.py` … 仕入先PDFをOCR/テキスト抽出し、
   候補値（見積書番号・日付・金額・明細）をJSON/テキストで出力する
   （Excelレビューシートは作らない。ここから先の確認・訂正はチャットで行う）
2. Claudeがチャットでのやり取りを `quote_automation/extraction/confirmed_quote.py`
   の `ConfirmedQuote` スキーマ（客先名・担当者名・件名・上乗せ率(%)・
   備考・明細）に沿ったJSONにまとめる
3. `step2_fill_template.py` … 確定済みJSONを `base_quote_template.xlsx` に転記する。
   出力ファイル名は自動的に `【見積書】<件名>.xlsx` になる
   （客先単価は `ROUNDUP(仕入単価×上乗せ率, -3)` で1000円単位に切り上げ、
   見積有効期限は `=TEXT(H3+30, "yyyy年m月d日")` で自動計算）
4. `step3_verify_calculation.py` … LibreOffice Calc(headless)で実際に再計算させ、
   Pythonで独立に計算した期待値と突き合わせる
5. `step4_export_pdf.py` … 検証OKのファイルだけをPDF化する（xlsxと同じ
   `【見積書】<件名>.pdf` になる）
6. `step2_fill_template.py` の中で `update_ledger.append_ledger_entry()` を呼び、
   `config.LEDGER_PATH`（`work/summary/quotation_ledger.xlsx`）に1行追記する
   （テスト実行時は `--skip-ledger` で追記を止められる）。仕入先名・仕入先担当者は
   仕入先PDFの見出し部分（発行元会社名・営業担当欄など）に書かれているので、
   通常はチャットで別途聞かなくても読み取れる
7. Claudeが `send_later`（MCP: claude-code-remote）で、見積り作成のおよそ1週間後に
   同じセッションへ受注状況確認のリマインダーを自分宛てにスケジュールする。
   これはPythonコードではなくClaude自身の運用（このステップの都度の振る舞い）

## 開発者向け：セッション開始フック

`.claude/hooks/session-start.sh` が、Claude Code on the webのセッション開始時に
自動で以下をインストールする。

- `tesseract-ocr`, `tesseract-ocr-jpn`（OCR）
- `libreoffice-calc`（数式再計算・PDF変換。Excelアプリは使わない）
- `quote_automation/requirements.txt` のPythonライブラリ
- `fonts-noto-cjk`＋`quote_automation/assets/fontconfig-local.conf`を`/etc/fonts/local.conf`に配置
  （テンプレートが指定するWindows専用フォント「Meiryo UI」がこの環境には無いため、
  見た目の近いNoto Sans CJK JPに差し替える。入れないとPDF変換時にフォントが
  意図しないものにフォールバックし、会社PCのExcelで見た時と印象が変わる）

このフックは同期実行（セッション開始がインストール完了を待つ）。起動を速くしたい
場合は非同期モードに変更できるが、その場合はインストール未完了のままスクリプトが
呼ばれるリスクがあるため、まずは同期のままにしている。
